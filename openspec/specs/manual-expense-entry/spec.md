# manual-expense-entry Specification

## Purpose
Let an administrator add expenses through the UI without a CSV import. The first and only supported category is annual hosting: an «Добавить» button on the Расходы tab opens a modal (year, site or «Общий», amount) that persists a `type = 'hosting'` row to the `expenses` table with the same idempotent (date, siteId, type) upsert semantics used by CSV import and the Gudok telephony ingest. Reuses the existing `expenses` table and its unique indexes; no schema change.

## Requirements
### Requirement: Ручное добавление годового хостинга

Система SHALL позволять администратору вручную добавлять расход типа `hosting` через UI вкладки «Расходы», без импорта CSV. Кнопка называется «Добавить» — такая же, как на вкладке доходов. Форма собирает год, сайт (или «Общий») и сумму в рублях; тип расхода зафиксирован как `hosting` и пользователем не выбирается и не отображается. Запись сохраняется в таблицу `expenses` с датой `YYYY-01-01` и суммой, конвертированной в целые копейки.

#### Scenario: Успешное добавление нового хостинга

- **WHEN** администратор нажимает «Добавить», выбирает год и сумму > 0 и подтверждает
- **THEN** система создаёт запись в `expenses` с `type='hosting'`, `date='<год>-01-01'`, `siteId` из выбора (или `null` для «Общий») и `amount` в копейках
- **AND** список расходов обновляется и показывает новую запись

#### Scenario: Сайт не выбран — общий расход

- **WHEN** администратор оставляет выбор сайта пустым («Общий (компания)»)
- **THEN** запись сохраняется с `siteId = null`

### Requirement: Идемпотентность по году, сайту и типу

Система SHALL трактовать повторное добавление хостинга за тот же год и сайт как обновление суммы, а не как ошибку — так же, как импорт и вебхуки ведут себя идемпотентно по `(date, siteId, type)`. Двух записей `hosting` с одинаковыми `(date, siteId)` не создаётся, что соответствует уникальным индексам таблицы `expenses`.

#### Scenario: Повтор за тот же год — сумма перезаписывается

- **WHEN** для года и сайта уже есть запись `hosting` и администратор добавляет хостинг за тот же год и сайт с другой суммой
- **THEN** система обновляет `amount` существующей записи и не создаёт новую строку

#### Scenario: Повтор с той же суммой — без изменений

- **WHEN** добавляется хостинг за год и сайт, где уже есть запись с той же суммой
- **THEN** данные не меняются (операция безопасна при повторе)

### Requirement: Только администратор

Система SHALL разрешать ручное добавление хостинга только пользователю с правами администратора, как и импорт CSV. Обычный пользователь не видит кнопку «Добавить» на вкладке расходов и не может выполнить действие на сервере.

#### Scenario: Обычный пользователь не видит кнопку

- **WHEN** страницу расходов открывает не-администратор
- **THEN** кнопка «Добавить» на вкладке расходов не отображается

#### Scenario: Серверная проверка прав

- **WHEN** запрос на добавление хостинга приходит от не-администратора
- **THEN** сервер отклоняет запрос (проверка `requireAdmin`)
